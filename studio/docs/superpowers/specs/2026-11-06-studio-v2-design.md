# SNS Studio v2 설계 — Edito 영감 기능 이식

2026-11-06 · 참고 캡처: `sns/refrence/editoapp/` (Edito iOS 앱 31장)

## 의도

카드뉴스 제작 앱 Edito(월 ₩9,900 구독)의 핵심 기능을 개인용 SNS Studio에 자가 구현한다.
상업용이 아닌 개인 운영 계정(@pickydoggyclub 외 4개)용. v1(현재 main)은 그대로 운영하고,
v2는 로컬에서 전부 테스트한 뒤 한 번에 배포한다.

## 목표 (우선순위 순 — 사용자 결정)

1. **장별 템플릿 선택** — 게시물당 템플릿 1개 → 슬라이드마다 선택. 표지/속지/마지막 장
   역할별로 어울리는 템플릿을 골라 한 게시물 안에서 혼합.
2. **속지 템플릿 3종 신설** (사용자 선택): 번호 소제목(넘버링), 리스트/정보 표, 아이템 소개.
3. **연재 관리** — 게시물을 연재로 묶고 호수 자동 증가, "다음 호 만들기"로 지난 호와 같은
   템플릿 조합 재사용. 호수는 **관리용으로만** 쓰고 카드 디자인에는 표시하지 않는다(사용자 결정).
4. **상세 텍스트·문단 스타일** — 자간·행간, 부분 강조(굵게·형광펜·글자색) 등.
5. **AI 캡션 초안** — 슬라이드에 쓴 제목·소제목·본문으로 인스타 캡션 초안 생성(자세히/짧게).
6. **하이브리드 저장** (사용자 결정) — 글·설정(post.json)은 Supabase 유지(수 KB라 부담 없음),
   미디어만 가볍게 관리. 폰 작성 → PC 내보내기 흐름은 유지해야 하므로 완전 로컬 저장은 하지 않는다.

## 비목표

- 사진 필터·효과 (사용자가 명시적으로 제외)
- 원고 붙여넣기 → 자동 장 분할 (Edito의 간판 기능이지만 이번 범위 아님)
- 글 점검·내 표기 사전·표지 점검·자유 배치 (요청 목록에 없음)
- 새 템플릿의 릴스(9:16) 대응 — 속지 3종은 캐러셀/단건 전용으로 시작

## 안티 목표 (이러면 실패)

- 미디어가 서버에 무한히 쌓여 Supabase 무료 한도(스토리지 1GB)에 닿는 것
- v2 완성 전에 main으로 머지되어 Vercel 프로덕션에 미완성 기능이 배포되는 것
- 기존 게시물(장별 template 필드 없는 post.json)이 열리지 않거나 다르게 렌더되는 것

## 제약

- 스택 고정: Next.js(App Router) + Supabase Storage + Vercel Hobby + Playwright/Chromium 내보내기.
- 템플릿 = `renderSlide()`가 완성 HTML 문자열을 반환하는 .mjs 모듈. 프리뷰(iframe)와
  내보내기(Playwright)가 같은 코드를 쓴다. 이 구조는 유지한다.
- 텍스트 필드 규칙 유지: 한 줄 = 디자인 한 줄, `data-max-lines` 초과·안전영역 넘침 시 빨간 표시.
- 브랜드 키트(brands/<id>.json)의 폰트·컬러가 모든 템플릿의 단일 소스. 폰트: Pretendard,
  Freesentation, Poppins (로컬 설치 + Vercel FONTCONFIG 복사본).
- 작업 브랜치: `v2` 장기 브랜치를 만들고 기능별 PR은 `v2`로 머지. main 머지(=배포)는
  사용자가 v2 완료를 선언할 때 한 번.
- 테스트 환경 (내 결정): 개발은 **로컬 파일 모드**(SUPABASE_URL 미설정 → content/ 폴더)로
  하여 운영 Supabase 데이터와 완전히 격리한다. v2가 쓰는 새 필드·마크업이 운영 v1 데이터에
  닿는 경로가 없다. main 머지 직전에 **별도 버킷**(SUPABASE_BUCKET만 교체)으로 Supabase
  전용 경로(서명 업로드, 미디어 정리 deletePrefix, 용량 합산)를 종단 테스트한다.

## 설계 결정 (결정자 표기)

### D1. 장별 템플릿 — 데이터 모델 (사용자 결정 + 구현 방식은 내 결정)

- `slide.template` 필드 신설. 없으면 `post.template` 폴백 → 기존 게시물 100% 호환.
- 템플릿 메타에 `role: 'cover' | 'inner' | 'any'` 추가. role은 선택 UI의 **그룹·정렬
  용도로만** 쓴다 — 어떤 경우에도 템플릿을 숨기지 않는다(내 결정). 1번 장에서는 cover·any
  그룹을 위에, 2장 이후에는 inner·any를 위에 보여줄 뿐이며, 단건(single) 게시물에서도
  전체 템플릿을 고를 수 있다. 기존 2종은 표지/내지 분기가 내장이므로 `role: 'any'`,
  신설 속지 3종은 `role: 'inner'`.
- 렌더러 호출부(프리뷰·내보내기·SVG)는 `getTemplate(slide.template ?? post.template)`로 바꾼다.
- 끝장(closing) 자동 첨부는 현행 유지(@<brand>/closing/ 첫 이미지).
- 기존 지식형(editorial-photo)의 표지/내지 분기(index===0)는 그대로 두되, 새 속지 템플릿은
  표지 분기 없이 단일 레이아웃으로 만든다.

### D2. 새 속지 템플릿 3종 (디자인 디테일은 빌더 재량)

공통: 1080×1350/1440 캐러셀·단건, 브랜드 ink/paper 컬러, 흰 배경 기반(Edito 속지 느낌),
좌우 여백 110px 그리드 준수(지식형 표지 레이아웃 기준과 통일), 출처 표기 없음.

1. `numbered-section` (번호 소제목): 상단에 `1.` 액센트 컬러 번호+소제목, 아래 본문 문단.
   필드: no(자동 아님, 직접 입력), title, body. 넘버링 꿀팁형 콘텐츠용.
2. `info-list` (리스트/정보 표): 제목 + 항목 리스트(라벨 + 설명, 최대 10줄 내외).
   체크리스트·비교 정리용.
3. `item-intro` (아이템 소개): `01.` + 아이템 이름 + 중앙 사진 칸 + 한 줄 설명 + 짧은 본문.
   추천템 콘텐츠용. 사진은 기존 미디어 핀(SHA-256) 체계 사용.

**필드 데이터 모델 (내 결정)**: 구조화 배열을 도입하지 않고 기존 **평면 textarea 체계를
유지**한다. info-list 항목은 한 줄 = 한 항목, `라벨 | 설명` 구분자 규칙(기존 출처 필드의
`출처 | ` 관성과 동일). 강조 줄은 D4의 `==형광펜==`/`{{색|…}}` 인라인 마크업으로 처리한다.
따라서 **마크업 파서(D4의 인라인 부분)는 D2보다 먼저** 구현한다 — 작업 순서 참조.
이 선택으로 에디터 필드 렌더링·오버플로 검사·textStyle 키 체계·캡션 수집 로직이
전부 기존 문자열 모델 그대로 동작한다.

### D3. 연재 관리 (내 결정)

- 저장: `content/<brand>/series.json` 하나에 배열로. Supabase 모드에선 같은 키로 저장.
  `{ id, title, nextNo, posts: [{ postId, no, title }] }`
- 게시물에 `series: { id, no }` 선택 필드.
- UI: 홈 목록에 연재 섹션 — 연재 만들기, 게시물을 연재에 넣기, "다음 호 만들기" 버튼.
  다음 호 = 지난 호 post.json에서 slides의 **템플릿·옵션·스티커 구성만** 복사하고
  텍스트·미디어는 비운 새 게시물 + 호수 자동 증가.
- 카드 디자인에 호수 비표시(사용자 결정). 캡션 초안에는 호수를 넣을 수 있게 컨텍스트로 전달.

### D4. 텍스트·문단 스타일 (내 결정 — 사용자 확인 필요로 빌더 체크에서 재검토)

두 층으로 나눈다:

- **필드 스타일(문단)**: 슬라이드 옵션 패널에 자간(letter-spacing)·행간(line-height)·
  크기 보정(±px) 슬라이더. `slide.textStyle = { [field]: { ls, lh, size } }`.
  템플릿 기본값에 덮어쓰는 방식이라 모든 템플릿에 공통 적용 가능.
- **부분 강조(인라인)**: 플레인 textarea를 유지하기 위해 경량 마크업을 쓴다.
  `**굵게**`, `==형광펜==`, `{{색|텍스트}}`(색 = 브랜드 액센트 팔레트 키).
  렌더러 공통 유틸(runtime.mjs)에서 escape 후 변환. 리치텍스트 에디터 도입은 하지 않는다
  (한 줄=한 줄 규칙·오버플로 검사 로직과 충돌 위험이 커서).

### D5. AI 캡션 초안 (내 결정)

- 기존 `/api/.../suggest`(ANTHROPIC_API_KEY, claude 호출) 옆에 캡션 모드 추가.
- 입력: 모든 슬라이드의 텍스트 필드 + 브랜드 보이스(brands JSON) + 연재 제목·호수(있으면).
- 출력: 자세히/짧게 2안, 해시태그 제안 포함. 에디터 캡션 칸 옆 ✨ 버튼 → 결과를 삽입/복사.
- 스타일 참조(references/headlines.json)는 제목용이므로 캡션에는 쓰지 않는다.

### D6. 하이브리드 저장 (사용자 결정 + 구체화는 내 결정)

- post.json 등 텍스트: 현행 Supabase 유지. 변경 없음.
- 미디어 경량화 두 가지만 추가:
  1. **용량 보기**: 설정/홈에 브랜드별 미디어 사용량 표시(Supabase list로 합산).
  2. **수동 '발행됨' 전환 + 정리** (사용자 결정): 홈/에디터에 '발행됨으로 표시' 버튼을
     신설한다. 실제 발행은 Meta Business Suite 예약발행이라 앱이 시점을 모르므로 수동
     전환이 운영 흐름에 맞다. 전환 시 "원본 미디어도 정리할까요?"를 물어 선택 시 미디어
     파일을 삭제하고 post.json에 `mediaPurged: true`와 파일명 목록만 남긴다. 기존 API
     발행 경로(publish/route.js)의 자동 status 설정은 그대로 두되 그 경로에서는 정리를
     묻지 않는다(재발행 안전). 내보내기 산출물(out/)은 git-ignore 로컬 전용이라 서버 부담 없음.
- 자동 삭제는 하지 않는다(실수 방지). 모든 정리는 명시적 버튼.

## 빌더에게 맡기는 것

- 새 템플릿 3종의 구체 수치(폰트 크기·간격)는 2026-11-06 폰트 개편(내지 소제목 36px Bold,
  본문 32px)과 레이아웃 기준(여백 110px)을 출발점으로 Edito 캡처를 참고해 조정.
- 에디터 UI 배치(템플릿 선택 드롭다운 위치, 연재 섹션 디자인)는 기존 에디터 관성 따름.
- 마크업 파서의 이스케이프 처리 순서(기존 escapeHtml 뒤 변환) 등 구현 세부.

## 작업 순서(큰 틀)

1. `v2` 브랜치 생성 → 장별 템플릿 데이터 모델 + 선택 UI (D1)
2. 인라인 마크업 파서 (D4의 부분 강조 — D2가 의존)
3. 속지 템플릿 3종 (D2)
4. 연재 관리 (D3)
5. 필드 스타일 슬라이더 (D4 나머지: 자간·행간·크기)
6. AI 캡션 초안 (D5)
7. 저장 경량화 (D6) → 스테이징 버킷 종단 테스트 → 사용자 승인 후 main 머지·배포
